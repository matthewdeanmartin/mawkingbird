# Unbird: the Twitter-to-Mastodon app (November 2026)

Status: sprints 1–2 implemented and uncommitted · 2026-11-17; awaiting the
owner's canary test. Sprints 3–4 planned. Cadence (owner, 2026-11-17): two
sprints at a time with light gates between them, a canary stop every two
sprints, full gates at the end of sprint 5 or 6.

## Why

Google Search Console shows Mawkingbird mostly to people searching to move from
Twitter to Mastodon. That search is the front door, and today it leads to:

- a settings panel (`settings/import-export/twitter-archive-import.*`) reused
  on `/twitter-to-mastodon/`, that is hard to find from inside the app;
- a page that reads as a wall of text ("OMG, I have to read so much"), about 30
  strings and three filters before any result;
- a hard first step: **unzip a multi-GB archive and pick the folder**;
- only 3 of ~75 archive files read (`following.js`, `tweets.js`,
  `deleted-tweets.js`);
- a sign-up path (`/welcome-back`) that relies on the user bookmarking us, and
  a `sessionStorage` archive hand-off that does not survive sign-up in another
  tab.

## Owner decisions (2026-11-17)

| Topic | Decision |
| --- | --- |
| Name | A new app mode, **Unbird**, in the switcher beside Fedi, RSS, Video, Radio. Same icon rules as the others ([top_level_menu.md](../top_level_menu.md)): Home, five tabs, switcher; one meaning per icon. |
| Additive | Everything is **additive**. The Settings importer and today's `/twitter-to-mastodon/` tool keep working alongside the new pieces. Nothing legacy is removed in this epic. |
| Value first | A visitor with **no account** can drop an archive and see who is already on Mastodon before being asked to sign up. Matching uses public lookups. |
| Sign-up | OAuth round trip: use `prompt=create` on servers that support it (Mastodon **5.0.0+**, see [OAuth docs](https://docs.joinmastodon.org/methods/oauth)), detected from `/api/v2/instance`. Older servers fall back to the existing welcome-back page. We never handle passwords. |
| Tweet replay size | **Best of, at most 300** per batch on the web, which is Mastodon's scheduled-post cap (50/day). Sized for small-to-medium archives; we are not doing 50k API calls. Native may queue more batches later. |
| What replays | **Originals and the user's own threads** only. Replies to other people are dropped: they are broken out of context and name handles that are not the same person on Mastodon. Retweets are dropped. |
| Mentions | **Always defused**: `@bob` becomes `bob`. On Mastodon a bare `@bob` resolves to whoever is `bob` on the user's server, which would ping a stranger. |
| Default posting | A quiet drip (unlisted) through the server's scheduler, so the tab can be closed. |
| Blocks and mutes | **Never imported, not even as a CSV.** A wrong follow corrects itself when you unfollow; a wrong block never does, because you never see the person again to notice. The archive has 19.5k blocks; one bad match is a silent permanent harm. Do not add this later without the owner. |
| Archive tools | A doorway for people who have a zip and no plan: **viewer and search, "your Twitter in numbers", likes shelf, export as a website**. Numbers are for the user, not a share card: there is nowhere to host one except a 500-character Mastodon post. |
| Contacts | `contact.js` is opened **only** when the user asks to **export contacts** to a phone-importable format (vCard). It is an archive tool, not a matching feature. |
| Privacy tone | Respect privacy without filling the UI with fear. One calm line ("Stays on your device · opens 8 of 75 files", with a "which?" disclosure), not warnings. |
| First sprint | Landing + People. |

## Facts from a real archive (owner's, counts only)

Read with the owner's permission; contents were not printed or kept.

| File | Records | Notes |
| --- | ---: | --- |
| `tweets.js` | 23,032 | 10,486 originals, 10,832 replies, 1,714 retweets, 680 with media, 157 with 10+ likes |
| `like.js` | 21,468 | Has `tweetId`, `fullText`, `expandedUrl`: a real shelf, not just IDs |
| `following.js` / `follower.js` | 1,646 / 1,339 | IDs and `userLink` only; handles must be recovered from tweets or lookups |
| `block.js` / `mute.js` | 19,525 / 739 | Not imported (see decisions) |
| `contact.js` | 1,300 | `emails`, `phoneNumbers`, **no names** |
| `lists-member.js` | 59 | Lists the user is *on*, not lists they made; `lists-created.js` was empty. Twitter-lists-to-Mastodon-lists is weak and is not planned. |
| `saved-search.js` | 3 | Could become followed hashtags |

- **There is no bookmarks file.** Twitter does not export bookmarks. "Import
  bookmarks" means likes, and likes can only become a local shelf, since the
  tweets still live on X.
- Large archives split files (`tweets-part1.js`, …) and sometimes the zip
  itself. The reader must handle both.
- Never opened: `account.js`, `phone-number.js`, `email-address-change.js`,
  DMs, `ip-audit.js`, `device-token.js`, ad and Grok files.

## Sprints

### 1. Landing + People

- **Zip reader.** Read the central directory with `File.slice`, inflate only
  allowlisted entries with `fflate`, and handle part files and split zips.
  Folder and loose-file picking still work.
- **Durable archive store.** Parsed, allowlisted data goes in IndexedDB,
  account-scoped once there is an account, with a "forget this archive" action.
  This replaces the `sessionStorage` hand-off for the new flow only.
- **Value-first matching** with no account: public `accounts/lookup` and
  profile-link signals, reusing `twitter-friend-discovery` scoring. It runs at
  full strength after sign-in.
- **Server matchmaking.** "Most of your people are on X and Y", combined with
  the handle generator checking the user's Twitter handle on those servers.
- **Sign-up round trip.** `prompt=create` with version detection; welcome-back
  as the fallback; returning lands on People with results waiting.
- **Unbird mode** in the switcher, with Start and People live. Unbuilt tabs do
  not appear yet.
- **New landing.** One drop target above the fold and the explanation
  collapsed below the tool (still indexed).

### 2. Archive tools doorway

Viewer with full-text search over tweets and likes, "your Twitter in numbers"
(local, not a share card), likes shelf linking authors who moved, export as a
static website (zip of HTML and RSS the user hosts), and contacts export to
vCard (opens `contact.js` only on that click).

### 3. Posts replay

Best-of picker (most liked, threads, media, date range) capped at 300; own
threads kept threaded through a tweet-ID to status-ID ledger; replies and
retweets stripped; mentions defused; t.co links expanded; media uploaded; an
"originally posted <date>" line; unlisted drip through scheduled statuses;
resumable.

### 4. Profile + Native

Profile bring-over, pinned "I moved" post, X bio text. Native: several import
points (several archives or several target accounts) on the Sprint 12 archive
store, plus a local queue beyond the 300-post web batch.

## Sprints 1–2: what was built (2026-11-17)

All new code is in `ui/src/app/unbird/` plus the public page
`discovery/twitter-archive-tools/`. Nothing legacy was removed.

- **Zip reader** (`archive-zip.ts`): central directory read with `Blob.slice`,
  Zip64, stored and deflate; only allowlisted entries are inflated. On the
  owner's real 247 MB archive it opened 7 of 74 data files in 0.6 s.
- **Archive model** (`unbird-archive.ts`): `READ_FILES` allowlist (manifest,
  profile, following, follower, tweets, like, saved-search; split parts
  count as their base). Owner handle comes from `manifest.js`, never
  `account.js`. People reuse the classic extractor and add mutuals and a
  closeness rank. Tweets keep text with t.co links expanded and are marked as
  thread posts, replies to others or retweets.
- **Device store** (`unbird-store.ts`): IndexedDB `mockingbird_unbird`
  (archive plus per-handle match results); wiped by the full sign-out
  teardown; "Forget it" clears it.
- **Matching** (`unbird-matcher.ts`): before sign-in, unauthenticated
  `/api/v2/search` on mastodon.social (no `resolve`); after, the reader's own
  server. Closest 120 first, then "Keep looking"; stops on 429 and resumes.
  Same strong-signal rule as the classic importer. Follow resolves the handle
  on the reader's server and is always a button press; "Follow all" covers
  likely matches only.
- **Server matchmaking** (`unbird-servers.ts`): top three servers among
  likely matches, the owner's Twitter handle checked on each, "Join X" links
  into `/login/mastodon?intent=need&server=X&next=/unbird/people`.
- **Sign-up round trip**: login reads `?intent=` and `?server=`; on the need
  path it probes `/api/v2/instance` (`signup-support.ts`). Mastodon 5.0+ gets
  "Create an account on X" which adds `prompt=create`; the in-flight OAuth
  record is also kept in localStorage (`mockingbird_oauth_signup`, registered
  as secret, two-hour expiry, consumed once) because email confirmation
  opens a new tab. Closed and approval-required servers say so. Older
  servers keep the welcome-back link. `/unbird`, `/unbird/people` and
  `/unbird/archive` are allowed `next` destinations.
- **Mode**: `unbird` in `APP_MODES`, switcher entry, tabs Start · People ·
  Archive, discovery rail widgets hidden like Radio. Routes are open to
  Anonymous.
- **`/twitter-to-mastodon/` takeover** (all 17 languages): the Unbird landing
  comes first; the how-to steps moved below the tool; English steps rewritten
  for "no need to unzip". **Deviation:** the classic importer stays on the
  same page inside a closed "Classic importer" disclosure (and in Settings)
  rather than at `/twitter-to-mastodon/classic/`, so no new routes, sitemap
  entries or translations were needed.
- **Archive tools** (`unbird-archive-tools.*`, public `/twitter-archive-tools/`):
  search (words, quoted phrases, kind, year, retweets opt-in), likes shelf,
  numbers (private, local time zone), website export (zip with a page per
  year, RSS feed, replies to others opt-in, retweets and likes never), and
  contacts export to vCard 3.0, which opens `contact.js` only on that click
  and asks to re-pick the archive after a reload. **Finding:** `like.js`
  has no author, so the likes shelf links to the tweet on X; "links to
  authors who moved" is not possible from the archive.
