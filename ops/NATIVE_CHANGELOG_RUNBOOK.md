# Writing the Native changelog

`NATIVE_CHANGELOG.md` in this repository is the source of truth. The private
`mawkingbird_native/CHANGELOG.md` is a byte-for-byte copy; never edit it there.
Building and publishing are in [NATIVE_RELEASE.md](NATIVE_RELEASE.md).

Git Bash, from this repository's root:

```sh
alias k='uvx --no-build --from keepachangelog-manager-fork==6.10.1 kaclm --component native'
```

## What an entry is

A sentence to someone who has the last release installed, about what is different
for them. It is not a commit, a ticket, a sprint result or a prompt.

Leave out:

- tests, refactors, formatting, build, dependencies, SEO, website-only pages;
- a fix for something that was never in a release (check the tag, below);
- anything that does not work in the desktop app, however finished it is on the web;
- behaviour behind a flag that is off in production;
- credit, effort, counts of files, and how it was built.

Write one bullet per thing a user would notice, about 25–30 for a large release.
Merge the rest. Say what it does, then its limit if there is one. Name the menu or
setting. Use the words on screen. It is Twitter, not X.

Use **Fixed** only when the last release did it wrong. If a default changed, that is
**Changed**, even when it arrived with a new feature.

## 1. Find what changed

Commit messages here don't say. Read the difference between the last tag and now.

```sh
BASE=$(git describe --tags --match 'native-v*' --abbrev=0); echo "$BASE"

# What users can read: every new, changed and removed English string.
git show "$BASE:ui/public/i18n/en.json" > /tmp/en-old.json
diff <(jq -S . /tmp/en-old.json) <(jq -S . ui/public/i18n/en.json) | less

# Where they can go, what is switched on, and what Native itself does.
git diff -w "$BASE" -- ui/src/app/app.routes.ts ui/src/app/platform/build \
  ui/src/app/platform/session/platform-login.native.ts \
  ui/src/app/platform/http/platform-http.native.ts
git diff --stat "$BASE" -- docs spec/sprint test_plans spec/test_plans

# The host. The private repo is ahead of native/, so compare against that.
rm -rf /tmp/native-base && mkdir /tmp/native-base && git archive "$BASE" native | tar -x -C /tmp/native-base
diff -ru --strip-trailing-cr /tmp/native-base/native/src-tauri ../mawkingbird_native/src-tauri \
  -x target -x gen -x autogenerated | less
```

A removed string may have been dead already, and `spec/sprint` says what was planned.
Both are leads, not evidence.

## 2. Check each candidate

1. **Is it new?** `git grep -n 'some string' "$BASE" -- ui/src`.
2. **For a fix: did the release have the bug?** Read the old code with
   `git show "$BASE:path"`. Not there, or the feature wasn't: leave it out.
3. **Does it work in Native?** Follow its request. Rust carries only what it lists:
   `mastodon_write.rs`, `public_mastodon.rs`, `bluesky.rs`, `misskey.rs` and the
   typed commands. Any other host is blocked by the content security policy. Check
   [the known gaps](../spec/native-transport-gaps.md). If unsure, leave it out.
4. **Which platforms?** Look for `cfg(target_os`. Say "on Windows" when it is.
5. **What is the default?** Read the preference; don't infer it from the copy.

## 3. Write

```sh
k add -t added -m "What you can now do."    # or changed, fixed, removed, deprecated, security
k remove --list
k validate
git diff NATIVE_CHANGELOG.md
```

`kaclm add` replaces the introduction at the top of the file with
its own. Restore it after the last command (the lines above `## [Unreleased]`) and
validate again. Editing wording by hand is fine; validate afterwards.

## 4. Copy to mawkingbird_native

```sh
make native-changelog         # validate, then copy to ../mawkingbird_native/CHANGELOG.md
make native-changelog-check   # fails if the two differ
```

Run it after every change to the file, including an automation-produced promotion once it has been reviewed. Set `NATIVE_REPO` if the
checkout is elsewhere. It commits nothing.

## 5. Hand off to release automation

Follow [NATIVE_RELEASE.md](NATIVE_RELEASE.md), especially its agent contract and
automation and mirror synchronization. Keep entries under `[Unreleased]`. The intended
workflow creates the draft, and publishing that draft triggers automated version
bookkeeping, a version-bump PR/MR, installer builds and attachments.

Do not run `kaclm release`, promote Unreleased or bump version files locally as
normal release preparation. If the workflows still demand those steps, report
and fix the automation; do not work around it by doing the steps yourself.

## Asking an agent to do this

Give it this file and `NATIVE_RELEASE.md`. Updating notes authorizes adding,
editing and validating Unreleased entries and copying the changelog. It does not
authorize promotion, version bumps, source deployment, tags, commits, pushes,
workflow dispatch or publication. It must list what it left out and why.
