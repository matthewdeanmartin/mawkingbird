# Sprint 11 — post tools and consolidation

Start with the full-tools/millions preview from Sprint 6. Integrate the reviewed
mixed button/link action group into StatusCard in provider/ownership batches.
Keep power-user actions visible and let them wrap. Preserve full counts and
separate count-list behavior, native reader/original links, keyboard reachability,
posting friction, preferences, authorization checks and destructive confirmations.

Build real fixtures for authenticated, anonymous, RSS/foreign, own post, busy,
failed action and large counts before each migration. Do not equate the superset
preview with every provider's actual capabilities. Review any change to defaults
or to the existing unified-share preference explicitly.

Consolidate shared tokens and remove superseded CSS after parity. Reconcile the
entire source inventory into individually reviewed migrations/exceptions/backlog;
expand narrow lint rules with positive/negative fixtures for adopted contracts.
Verify the hosted catalogue job and document ownership and recurring audit cadence.

Exit: actual consumer counts, no hidden unclassified remainder, tested contracts
for public widgets, preserved initial budget, and an honest residual backlog.
Do not label all five sprints complete merely because previews exist.
